# Slufter3D

A walkable first-person 3D model of Landal Sluftervallei, the holiday park in the dunes of Texel. Built from 
height data (AHN) and the national topographic map (BGT). Runs in a browser as
WebAssembly, served as static files from `docs/`.

This is a rebuild of an earlier C++/WebAssembly version. The guiding rule of the rebuild: raw data stays raw,
every interpretation of it is a separate, regenerable file.

## Layout

```
raw/        measured data exactly as downloaded. Never edited, never regenerated. Read-only.
data/       interpretation of the raw data: which pixel is a house, which triangle is a road. Checked in,
            but every file here can be regenerated from raw/ by a script in tools/.
core/       small, generic building blocks (vectors, matrices, colour, the triangle mesh) used everywhere.
models/    one C++ file per kind of building, tent, or other object the world is built from.
src/        the application itself: loading the world, walking and flying through it, drawing the scene.
tools/      Python scripts that turn raw/ into data/, and data/ into the packed world file.
tests/      C++ unit tests (native) and a Node smoke test of the built WebAssembly.
docs/       the web page itself: HTML, JS, the built .wasm, and the packed world data. Served by GitHub Pages.
build/      everything generated by `make` or by a tool in tools/: object files, previews, intermediate
            rasters. Never checked in.
```

### `raw/` — measured data, read-only

- `raw/ahn/` — height data from the AHN (Actueel Hoogtebestand Nederland), the Dutch national elevation
  survey. For each of three areas (`park` at 0.5 m resolution, `tip` at 2 m, `horizon` at 5 m) there is a
  **DTM** (`*_dtm_*.tif`, Digital Terrain Model: the ground, with vegetation and buildings filtered out) and
  a **DSM** (`*_dsm_*.tif`, Digital Surface Model: whatever the laser actually hit first — a roof, a treetop,
  the bare ground where nothing stands). Each `.tif` has a sidecar `.tif.json` recording how it was fetched and
  a checksum. Downloaded by `tools/fetch_ahn.py`. Licence: CC0 (Rijkswaterstaat) — no attribution legally
  required, but credited anyway.
- `raw/bgt/` — topography from the BGT (Basisregistratie Grootschalige Topografie), the Dutch large-scale
  topographic register: building outlines (`pand*.json`), roads (`wegdeel*.json`,
  `ondersteunendwegdeel*.json`), water (`waterdeel*.json`), and vegetated/unvegetated ground
  (`begroeidterreindeel*.json`, `onbegroeidterreindeel*.json`). Downloaded by `tools/fetch_bgt.py`, paged
  automatically, limited to the rectangle covering the park, the sea, and the lighthouse. Objects carry an
  `eind_registratie` field; a non-null value marks a historic (superseded) version, which every reader of
  this data filters out. Licence: CC BY 4.0 (Kadaster) — attribution required, given in `docs/index.html`.
- `raw/slufter_v1/houses.json` — a frozen export of the house table from the first (pre-AHN) version of
  Slufter, kept as a cross-check and a source of information the AHN/BGT data cannot supply by itself (type,
  name, which houses pair up as a semi-detached block).
- `raw/topotijdreis/` — screenshots of the topographic map 1:25 000 of 1965, 1983 and 1994 from Topotijdreis
  (Kadaster), each beside the map of 1998 at the same scale. On them every bungalow of the park as it was from
  1957 to 1996 is a dot. See its `README.md`.
- `raw/park_1957_1996/` — photographs of that park, by their own names, which say what they show.

### `data/` — interpretation, regenerable

- `data/houses.json` — every house, cabin and camping pitch: position, size, orientation, type, and which
  AHN building it was matched to. Built by `tools/make_houses.py` from `raw/ahn` + `raw/bgt/pand*` +
  `raw/slufter_v1/houses.json`.
- `data/house_corrections.json` — manually reviewed exceptions to that automatic matching (accepted matches
  that failed an automatic check, buildings in the AHN with no house on the park map, buildings left out of the
  world because no model fits them, buildings of another type than the park map gives, buildings whose outline
  was measured on photographs because the AHN gets it wrong, houses that stand the other way round, such as the
  12Ls whose low wing the BGT puts at the other end, and so on).
- `data/type_models.json` — maps a house *type* on the park map (`"8C"`, `"4MH"`, ...) to the C++ model that
  draws it (`models/Comfort8C.cpp`, ...).
- `data/landmarks.json` — fixed points that are not houses: the lookout tower, the Reception entrance, the
  lighthouse, where a visitor starts (over the lookout tower).
- `data/old_park.json` — the buildings of the park as it was from 1957 to 1996: number, name, kind (bungalow
  or chalet), type (A4, A6, B4, B6), the way the front door faces, position; `Unknown` where a thing is
  not known. Built by `tools/make_old_park.py` (`make oldpark`). The map of the park's own brochure
  (`raw/park_brochures`, read by hand into `data/old_park_brochures.json`) says which bungalows there were, with
  their number and type; the topographic maps (`raw/topotijdreis`) say where, wherever they show the bungalow.
  It also writes `review/old_park/`: the dots found on each topographic map, `old_park_all_maps.png` (all four
  maps and the place decided on, on the relief of today), and a table. The type gives the door and the model
  in `data/type_models.json`: A4 red, A6 green, B4 yellow; B6 are the chalets.
  `tools/pack_world.py` puts them in the world file beside the houses of today, each with the eras it stands
  in: the page has a list of four, 1957–1971 (the white bungalows), 1971–1993 (with the chalets, drawn as safari
  tents for now), 1993–2013 (the Comfort bungalows) and 2013–today (with the Luxe bungalows). A front that is
  not known faces west, so that the terrace, right of the front door, faces south. The ground, the
  trees and the central building are those of today in every era; an old bungalow where the central building
  stands is not drawn. An old building is found by its number on the park map (Go), and shows it with its type.
  The roads differ per era too: before 1993 the park had the roads of the park map, all unpaved. Only what the
  map draws as a road counts: the thick ring road and the gravel roads drawn as two thin lines; a thin single
  line is the edge of a dune. The roads of the caravan and tent fields are left out. An old road lies on the
  road of today wherever that is within 8 m, and where the park map has it elsewhere, and wherever the road of
  today runs over an old bungalow (`review/old_park/old_park_roads.png`). The roads of today within the park
  are shown from 1993; those outside it in every era.
- `data/old_park_corrections.json` — the dots that lie under a label of the topographic map, read by eye; what
  kind each type is; names, fronts and the door colours seen in photographs, by number; each with its reason.
- `data/old_park_photos.json` — where the tower and a number of buildings stand in three of the photographs.
  `tools/check_old_park_photos.py` finds from them where each was taken and how far each building lies from
  its line of sight: the check on the names.
- `data/trees.json` — every tree found in the AHN height data: position, height, and crown radius. Built by
  `tools/make_trees.py` from `raw/ahn` + `build/terrain` (see below).

### `core/`, `models/`, `src/` — the C++ application

- `core/` — `Math.h` (vectors, matrices), `Color.h`, `Mesh.h`/`.cpp` (a triangle soup with baked lighting,
  the thing every model and every part of the scene is drawn into).
- `models/` — one `Model` subclass per kind of thing in the world (`Comfort6C`, `Luxe8L`, `Tent`,
  `SafariTent`, `Lighthouse`, `LookoutTower`, `ScotsPine`, ...), plus the shared `ModelKit`/`PlanKit`
  construction helpers used to build gabled houses from a floor plan, and `ComfortKit`, the brick, frames, slate
  gables and paving of the Comfort bungalows. The two halves of a 4C block are one model, `Comfort4C`: the world
  stands one half 1.22 m back from the other, as in the BGT, and draws it as the mirror image of the model.
- `src/` — `WorldData` (reads the packed `world.bin`), `Terrain` (the ground, as a set of grids at different
  resolutions), `World` (houses placed on the terrain, collision/standability queries, and how high above each spot nothing is
  in the way: just above its railings over the lookout tower, 12 m elsewhere), `Walker` (the
  visitor's movement: walking at three speeds, flying, rising, landing), `Scene` (builds one big `Mesh` for
  the whole world and the camera's view/projection matrix; the ground gets its colour and light at the nodes of
  the grids, blended across the tiles, with gentle patches of drier and lusher vegetation from a fixed noise;
  the land comes right after the sky, so that the page can draw it apart), `Game` (ties it together: input,
  HUD text, go-to-house), `wasm_api.cpp` (the `SLUFTER_EXPORT`-ed C functions the JavaScript side calls).

### `tools/` — the pipeline, raw/ → data/ → docs/data/world.bin

Run in this order; each step is idempotent and only reads what the previous one wrote:

1. `fetch_ahn.py`, `fetch_bgt.py` — one-time, write-once downloads into `raw/`. Re-run only to add new
   rectangles; never to replace what's already there (they refuse to overwrite).
2. `make_houses.py` — raw/ → `data/houses.json`. Fits the old survey onto the AHN building outlines and
   writes a review image for anything uncertain (`build/review/houses_review.png`).
3. `make_terrain.py` — raw/ + `data/houses.json` → `build/terrain/*.tif` + `build/terrain/terrain.json`.
   Decides what every gap in the DTM means (building, water, or sea) and computes the ground level under
   every house's floor.
4. `make_trees.py` — raw/ + `build/terrain/` + `data/houses.json`/`raw/bgt/pand*` → `data/trees.json`. What stands
   above the ground and is not a building or water is a tree; every top of that canopy becomes one tree. Also
   writes a preview (`build/preview/trees/trees.png`).
5. `pack_world.py` — `build/terrain/` + `data/*.json` → `docs/data/world.bin`, the single binary file the
   C++ application loads at runtime. Every tile of the ground carries its inland water level, or a mark that
   it is sea as `make_terrain.py` found it; the application takes nothing else for sea, so low ground inland
   (the polder, below 0 m NAP) stays land. Also writes a road preview (`build/preview/world/roads.png`).

`check_data.py` runs a battery of sanity checks over `data/` (every house has a model, no duplicate house
numbers, fronts square to their axis, nothing lies outside the measured area, ...). Part of `make test`.

### `tests/`

- `test_models.cpp` — every model, built once and compared byte-for-byte against a golden dump
  (`tests/golden/`), so a change to geometry is always visible in a diff.
- `test_world.cpp` — loads the real `docs/data/world.bin` and checks the whole pipeline end to end: terrain
  seams line up, houses stand on their ground, the colours of the ground run on across its tiles, the land
  comes right after the sky, roads and water are drawn flat and last, walking and flying behave, the HUD string has the right shape.
- `smoke.mjs` — the same kind of checks, but against the actual built `.wasm`, run under Node: the one test
  that exercises the real WebAssembly boundary (`slufter_init`, `slufter_step`, ...).

### `docs/` — what GitHub Pages serves

`index.html` + `slufter.js` (the page, canvas, input handling, WebGL drawing) + `slufter.wasm` (built by
`make wasm`) + `data/world.bin` (built by `make world`). Nothing here is hand-written data; `slufter.js` is
the one file of real logic (mostly: load the two files, translate keyboard/mouse/touch into the
`slufter_set_controls`/`slufter_set_pace`/... calls, draw the returned triangle buffer). On the land of the
park it draws the 3 m tiles of its grid a little lighter and darker in turn, averaged over every pixel, so that
far away they blend into an even colour instead of shimmering; without WebGL's derivatives it fades them out
within 50 m instead. The weather is the page's too: fog, overcast and the evening fade the land over a shorter
distance, take some of its colour away, tint it and colour the sky anew. The light on the land stays as the world
was built, with the sun in the south-west; *Day* is the world as built.

## Building and running

Needs a C++17 compiler (`c++`), [Emscripten](https://emscripten.org/) (`em++`) for the WebAssembly build,
Node for the smoke test, and Python 3 with `numpy`, `scipy`, `rasterio`, `shapely`, `matplotlib` for the
tools.

```sh
make test     # native unit tests + data checks — no Emscripten needed
make wasm     # docs/slufter.wasm
make smoke    # a short scripted visit through the built .wasm, under Node
make serve    # http://localhost:8000, serving docs/
```

To regenerate the data pipeline (only needed after touching `raw/`, `data/*.json`, or a tool):

```sh
make houses   # data/houses.json
make trees    # data/trees.json            (THRESHOLD=1.0 by default, see tools/make_trees.py)
make world    # build/terrain/ + docs/data/world.bin
```

Deploying is simply committing `docs/` — GitHub Pages serves it directly; no server-side build step.

## Controls

Walk with `W`/`S` or the arrow keys, turn with `A`/`D`, step sideways with `Q`/`E`, look around by dragging.
Fly: mouse wheel or `Space`/`C` to rise or descend; `L` to land. `1`/`2` switch between walking speeds (Slow,
20 km/h; Fast, 50 km/h). The visit starts on the lookout tower, just above its railings, looking east, and `R`
returns there. Both land you there, as *Land* does: you stay on the tower until you walk off it, and then come
down beside it. Landing over the tower ends there too, and lower than its railings the tower stops you like a
wall. A number box and *Go* jump to a given house. On the panel, a tap on *Up* or *Down* is one step and holding
it keeps climbing or descending; *Land* comes down to the ground; *Trees* (`T`) and *Tiles* (`G`), both on at the start, show or hide the trees and
the tiles on the ground; the drop-down beside them sets the weather (*Day*, *Fog*, *Overcast*, *Evening*), and
`F` steps through it. On a
phone, round buttons walk and turn, and nothing on the page can be selected
but the house number, so that every press reaches its button.
