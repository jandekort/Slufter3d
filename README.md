# Slufter3D

A walkable first-person 3D model of Landal Sluftervallei, the holiday park in the dunes of Texel. Built from
measured height data (AHN) and the national topographic map (BGT), not from guesswork. Runs in a browser as
WebAssembly, served as static files from `docs/`.

This is a rebuild of an earlier C++/WebAssembly version. The guiding rule of the rebuild: raw data stays raw,
every interpretation of it is a separate, regenerable file, and nothing is added to the repository without
discussing it with Jan first.

## Layout

```
raw/        measured data exactly as downloaded. Never edited, never regenerated. Read-only.
data/       interpretation of the raw data: which pixel is a house, which triangle is a road. Checked in,
            but every file here can be regenerated from raw/ by a script in tools/.
core/       small, generic building blocks (vectors, matrices, colour, the triangle mesh) used everywhere.
models/    one C++ file per kind of building, tent, or other object the world is built from.
src/        the application itself: loading the world, walking and flying through it, drawing the scene.
tools/      Python scripts that turn raw/ into data/, and data/ into the packed world file.
tests/      C++ unit tests (native) and a Node smoke test of the built WebAssembly.
docs/       the web page itself: HTML, JS, the built .wasm, and the packed world data. Served by GitHub Pages.
build/      everything generated by `make` or by a tool in tools/: object files, previews, intermediate
            rasters. Never checked in.
```

### `raw/` — measured data, read-only

- `raw/ahn/` — height data from the AHN (Actueel Hoogtebestand Nederland), the Dutch national elevation
  survey. For each of three areas (`park` at 0.5 m resolution, `tip` at 2 m, `horizon` at 5 m) there is a
  **DTM** (`*_dtm_*.tif`, Digital Terrain Model: the ground, with vegetation and buildings filtered out) and
  a **DSM** (`*_dsm_*.tif`, Digital Surface Model: whatever the laser actually hit first — a roof, a treetop,
  the bare ground where nothing stands). Each `.tif` has a sidecar `.tif.json` recording how it was fetched and
  a checksum. Downloaded by `tools/fetch_ahn.py`. Licence: CC0 (Rijkswaterstaat) — no attribution legally
  required, but credited anyway.
- `raw/bgt/` — topography from the BGT (Basisregistratie Grootschalige Topografie), the Dutch large-scale
  topographic register: building outlines (`pand*.json`), roads (`wegdeel*.json`,
  `ondersteunendwegdeel*.json`), water (`waterdeel*.json`), and vegetated/unvegetated ground
  (`begroeidterreindeel*.json`, `onbegroeidterreindeel*.json`). Downloaded by `tools/fetch_bgt.py`, paged
  automatically, limited to the rectangle covering the park, the sea, and the lighthouse. Objects carry an
  `eind_registratie` field; a non-null value marks a historic (superseded) version, which every reader of
  this data filters out. Licence: CC BY 4.0 (Kadaster) — attribution required, given in `docs/index.html`.
- `raw/slufter_v1/houses.json` — a frozen export of the house table from the first (pre-AHN) version of
  Slufter, kept as a cross-check and a source of information the AHN/BGT data cannot supply by itself (type,
  name, which houses pair up as a semi-detached block).

### `data/` — interpretation, regenerable

- `data/houses.json` — every house, cabin and camping pitch: position, size, orientation, type, and which
  AHN building it was matched to. Built by `tools/make_houses.py` from `raw/ahn` + `raw/bgt/pand*` +
  `raw/slufter_v1/houses.json`.
- `data/house_corrections.json` — manually reviewed exceptions to that automatic matching (accepted matches
  that failed an automatic check, buildings in the AHN with no house on the park map, and so on).
- `data/type_models.json` — maps a house *type* on the park map (`"8C"`, `"4MH"`, ...) to the C++ model that
  draws it (`models/Comfort8C.cpp`, ...).
- `data/landmarks.json` — fixed points that are not houses: the lookout tower, the Reception entrance, the
  lighthouse, where a visitor starts.
- `data/trees.json` — every tree found in the AHN height data: position, height, and crown radius. Built by
  `tools/make_trees.py` from `raw/ahn` + `build/terrain` (see below). **Work in progress — see `PROMPT.txt`.**

### `core/`, `models/`, `src/` — the C++ application

- `core/` — `Math.h` (vectors, matrices), `Color.h`, `Mesh.h`/`.cpp` (a triangle soup with baked lighting,
  the thing every model and every part of the scene is drawn into).
- `models/` — one `Model` subclass per kind of thing in the world (`Comfort6C`, `Luxe8L`, `Tent`,
  `SafariTent`, `Lighthouse`, `LookoutTower`, `ScotsPine`, ...), plus the shared `ModelKit`/`PlanKit`
  construction helpers used to build gabled houses from a floor plan.
- `src/` — `WorldData` (reads the packed `world.bin`), `Terrain` (the ground, as a set of grids at different
  resolutions), `World` (houses placed on the terrain, collision/standability queries), `Walker` (the
  visitor's movement: walking at three speeds, flying, rising, landing), `Scene` (builds one big `Mesh` for
  the whole world and the camera's view/projection matrix), `Game` (ties it together: input, HUD text,
  go-to-house), `wasm_api.cpp` (the `SLUFTER_EXPORT`-ed C functions the JavaScript side calls).

### `tools/` — the pipeline, raw/ → data/ → docs/data/world.bin

Run in this order; each step is idempotent and only reads what the previous one wrote:

1. `fetch_ahn.py`, `fetch_bgt.py` — one-time, write-once downloads into `raw/`. Re-run only to add new
   rectangles; never to replace what's already there (they refuse to overwrite).
2. `make_houses.py` — raw/ → `data/houses.json`. Fits the old survey onto the AHN building outlines and
   writes a review image for anything uncertain (`build/review/houses_review.png`).
3. `make_terrain.py` — raw/ + `data/houses.json` → `build/terrain/*.tif` + `build/terrain/terrain.json`.
   Decides what every gap in the DTM means (building, water, or sea) and computes the ground level under
   every house's floor.
4. `make_trees.py` — raw/ + `build/terrain/` + `data/houses.json`/`raw/bgt/pand*` → `data/trees.json`. See
   `PROMPT.txt`.
5. `pack_world.py` — `build/terrain/` + `data/*.json` → `docs/data/world.bin`, the single binary file the
   C++ application loads at runtime. Also writes a road preview (`build/preview/world/roads.png`).

`check_data.py` runs a battery of sanity checks over `data/` (every house has a model, no duplicate house
numbers, fronts square to their axis, nothing lies outside the measured area, ...). Part of `make test`.

### `tests/`

- `test_models.cpp` — every model, built once and compared byte-for-byte against a golden dump
  (`tests/golden/`), so a change to geometry is always visible in a diff.
- `test_world.cpp` — loads the real `docs/data/world.bin` and checks the whole pipeline end to end: terrain
  seams line up, houses stand on their ground, roads and water are drawn flat and last, walking and flying
  behave, the HUD string has the right shape.
- `smoke.mjs` — the same kind of checks, but against the actual built `.wasm`, run under Node: the one test
  that exercises the real WebAssembly boundary (`slufter_init`, `slufter_step`, ...).

### `docs/` — what GitHub Pages serves

`index.html` + `slufter.js` (the page, canvas, input handling, WebGL drawing) + `slufter.wasm` (built by
`make wasm`) + `data/world.bin` (built by `make world`). Nothing here is hand-written data; `slufter.js` is
the one file of real logic (mostly: load the two files, translate keyboard/mouse/touch into the
`slufter_set_controls`/`slufter_set_pace`/... calls, draw the returned triangle buffer).

## Building and running

Needs a C++17 compiler (`c++`), [Emscripten](https://emscripten.org/) (`em++`) for the WebAssembly build,
Node for the smoke test, and Python 3 with `numpy`, `scipy`, `rasterio`, `shapely`, `matplotlib` for the
tools.

```sh
make test     # native unit tests + data checks — no Emscripten needed
make wasm     # docs/slufter.wasm
make smoke    # a short scripted visit through the built .wasm, under Node
make serve    # http://localhost:8000, serving docs/
```

To regenerate the data pipeline (only needed after touching `raw/`, `data/*.json`, or a tool):

```sh
make houses   # data/houses.json
make trees    # data/trees.json            (THRESHOLD=1.0 by default, see tools/make_trees.py)
make world    # build/terrain/ + docs/data/world.bin
```

Deploying is simply committing `docs/` — GitHub Pages serves it directly; no server-side build step.

## Controls

Walk with `W`/`S` or the arrow keys, turn with `A`/`D`, step sideways with `Q`/`E`, look around by dragging.
Fly: mouse wheel or `Space`/`C` to rise or descend; `L` to land. `1`/`2` switch between walking speeds (Slow,
20 km/h; Fast, 50 km/h). `R` returns to the lookout tower. A number box jumps to a given house.
